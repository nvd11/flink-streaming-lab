# Lab 05 深度设计规格：会话窗口与动态动账分析

## 1. 业务场景：连续消费行为捕捉 (Sessionization)
现实生活中，人的消费行为往往不是按“整点/自然分钟”均匀分布的，而是呈现**突发集中性（Bursty）**：
- **场景 A：商场周末逛街**：14:00 停车缴费 -> 14:15 喝奶茶 -> 14:40 吃午饭 -> 15:10 衣服采买 -> 随后长达 4 小时无消费。
- **场景 B：信用卡风控盗刷防范**：短时间内（30秒内）连续在不同商户发起小额试探交易。

这种**以“静默超时（Inactivity Gap）”为边界切分**的窗口，称为**会话窗口（Session Window）**。

## 2. 会话窗口状态合并哲学 (Window Merging)
滚动窗口与滑动窗口的边界是固定的，而会话窗口在开始时为每一个事件创建一个独立的微型窗口 $[t, t + \text{gap})$。
当新事件到达且其时间范围与既有微型窗口重叠时，Flink 会**动态触发窗口合并（Window Merge）**：
- 事件 1: $10:00:00 \implies [10:00:00, 10:15:00)$
- 事件 2: $10:08:00 \implies [10:08:00, 10:23:00)$
- **触发 Merge**: 两个窗口合并为 $[10:00:00, 10:23:00)$！

### 聚合累加器的合并契约
实现增量预聚合时，`AggregateFunction` 必须实现 `merge(ACC a, ACC b)`：
```java
@Override
public TxSummaryAccumulator merge(TxSummaryAccumulator a, TxSummaryAccumulator b) {
    a.mergeFrom(b);
    return a;
}
```

## 3. 实验验证目标与断言
1. **单会话动态延展断言**：在间隙（如 10 分钟）内连续注入 4 笔动账，验证最终仅输出 1 个会话窗口，且起止时间覆盖第 1 笔至最后 1 笔动账。
2. **多会话分裂断言**：当两笔动账间隔超过 10 分钟时，验证系统清晰分裂为 2 个独立的会话统计报告。
3. **风控规则断言**：在会话窗口中实现风控告警逻辑（如会话内交易笔数 $\ge 3$ 且跨商户数 $\ge 3$ 触发高频预警）。
