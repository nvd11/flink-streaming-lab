# Lab 02 深度设计规格：窗口生命周期与迟到三部曲

## 1. 实验背景与业务痛点（账本已经合上了，银行才慢吞吞补发旧短信怎么办？）
真实金融场景中，跨行转账或网关拥堵的动账短信常常在窗口初次结算后数分钟、乃至半小时后才送达。如果 5 分钟窗口仅仅在 Watermark 到达时“一刀切”彻底销毁并丢弃迟到数据，会导致**大额转账漏报**或**账目永久失衡**。

### 核心业务案例映射
针对单卡（`cardTail = "8888"`）的 `[10:00:00, 10:05:00)` 5 分钟统计窗口，Flink 构建了**迟到治理的三道防线**：
1. **第一道防线（小迟到：多等几秒再结账）**：`WatermarkStrategy.forBoundedOutOfOrderness(10s)` —— 容忍几秒内的轻微网络乱序；
2. **第二道防线（中度迟到：翻开刚合上的账本重算并补报预警）**：`allowedLateness(1min)` —— 窗口在 `10:05:00` 首次结账（当时转账 `4000 元`，未满 5000 不报警，`version = 1`）后**先不销毁账本**；若在 1 分钟宽限期内收到一笔属于 `10:03:00` 的迟到转账 `2000 元`，立即翻开账本重算为 `6000 元 > 5000 元`，**补发一条修正版超额报警（`transferAlert = true, version = 2`）**！
3. **第三道防线（严重迟到：登记进错账本备查）**：`sideOutputLateData(LATE_TAG)` —— 超过 1 分钟宽限期（如半小时后才到）的老掉牙短信，不再翻旧账，而是 100% 捕获进“迟到错账本（侧输出流）”留底审计。

## 2. 状态机与窗口触发推演
设单卡滚动窗口为 5 分钟：$[10:00:00, 10:05:00)$
- 乱序容忍度：10 秒 (`forBoundedOutOfOrderness(10s)`)
- 允许迟到宽限期：1 分钟 (`allowedLateness(1m)`)
- 侧输出标签：`OutputTag<FinancialTxEvent> LATE_OUTPUT_TAG`

### 时钟生命周期时间线
```text
Event Time:      10:00:00 -------------- 10:05:00 ------- 10:05:10 ----------- 10:06:10 ---->
Window [00, 05): |<--- 正常接收 5 分钟支出 --->|
Watermark:                                               到达 10:05:00 (由 10:05:10 事件触发)
                                                         首次结账 Fire (v1): 转账累计 4000 元 (未超 5000, alert=false)
                                                         |<-- 1min allowedLateness 宽限期 -->|
                                                                ▲                            Watermark 到达 10:06:00
                                                       迟到转账 2000 元(10:03)到达!           窗口状态彻底销毁 Clean
                                                       二次重算 Fire (v2):                   此后到达的旧短信(如 10:02)
                                                       转账累计 6000 > 5000 -> 补发警报!     100% 落入 SideOutput 错账本
```

## 3. 实验验证目标与断言
1. **首次结账断言 (Fire v1)**：当 Watermark 推进至 `10:05:00` 时，窗口首次触发，输出 `totalTxCount = 2, transferAmount = 4000.00, transferAlert = false, triggerVersion = 1`。
2. **二次重算补报断言 (Fire v2)**：在宽限期内到达属于 `[10:00, 10:05)` 的 `2000.00 元` 迟到转账后，窗口再次触发，输出修正记录 `totalTxCount = 3, transferAmount = 6000.00, transferAlert = true, triggerVersion = 2`（成功追回大额转账报警！）。
3. **侧输出错账本兜底断言**：当 Watermark 超过窗口销毁线（`10:06:00`）后，再到达的 `10:02:00` 迟到支出不再触发主流窗口计算，而是 100% 在 `SideOutput` 中被精准捕获。
